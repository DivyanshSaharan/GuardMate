# Untuned Qwen validation baseline — October 3, 2026

This is a small **development validation run**, not a frozen final test, fine-tuning result,
field trial or evidence of reduced parcel returns. The model was `Qwen/Qwen3.5-4B` through Tinker,
thinking disabled, temperature 0.2, 12,000 maximum input tokens and 512 maximum output tokens.
No model training has been performed.

## Data and procedure

All six validation scenarios were replayed, with 19 total steps and 13 real model requests.
Resident decisions and context changes used the real engine with a simulated clock. Conversations
and fictional resident settings were held in isolated temporary stores; the existing persistent
budget ledger was shared. No real resident preference or conversation was modified.

The dataset has 27 draft seeds: 24 synthetic authored conversations and three user-reported
questions expanded with fictional surroundings. The three user-derived seeds are train-only,
not part of this validation run. These draft labels are provisional: reference replay checks
agreement with the engine, not independent human review or broad generalization.

Command:

```powershell
.venv\Scripts\python backend\scripts\evaluate_delivery.py --live --split validation --max-calls 13 --max-cost-usd 0.06 --output .data/evaluation/base-validation-20261003.json
```

The generated per-step report is ignored local runtime data. Use a new output filename to rerun;
existing artifacts are never overwritten. Sampling is not deterministic, so a repeated run may
produce different results. The command returned exit code 1 because rubrics failed, not because
the provider failed or the run was interrupted.

The latency set contains 13 samples, including cold initialization. These are not microphone-to-audio
response times. Zero forbidden authorizations in this small annotated suite is not a real-world
safety guarantee. Strict plan matching also checks explicitly represented observations, so it can
fail a plan whose checked conversational action was acceptable. See the evaluation guide for definitions.

### Failure analysis

- `validation-profile-change` and `validation-availability-change`: Qwen omitted the explicit
  guard-absence observation and asked about guard presence instead of requesting approval for
  the proposed alternative. No approval was created, so the following scripted resident/context
  steps failed too. These downstream failures are not independent model mistakes.
- `validation-unknown-then-absent`: Qwen proposed an unmentioned `reception` location. The
  application rejected it and asked for an exact alternative. The checked workflow passed while
  the planner rubric failed. A later takeover plan also restated absence without a supporting quote.
- `validation-future-versus-completed`: Qwen attempted to record delivery from a future intention.
  The application refused and asked whether it had actually happened. Again, the checked workflow
  passed while the plan was wrong.
- `validation-signature-after-directions`: the takeover was correctly executed, but the model
  omitted the simultaneously stated payment/presence observations and failed strict plan matching.

This is why application success and raw planner correctness are separate. Any later fine-tune should
target these defects without removing the independent permission checks. Do not claim improvement
from a new prompt, changed checker or changed dataset unless those changes are separately controlled.

## Budget evidence

The run allowed at most 13 calls and $0.06 in worst-case estimated reservations. Its per-attempt
maximum admission total was $0.058175. The shared ledger increased by **$0.015419**, from $0.077345
to **$0.092764**, within the unchanged $0.25 cumulative inference cap. No training credits were used.
The ledger is conservative reservation accounting, not provider billing; simultaneous UI activity
can contribute to its change. Adapter rates were checked against [Tinker model pricing](https://tinker-docs.thinkingmachines.ai/tinker/models/models_and_pricing/)
on October 3, 2026. Preserve the existing ledger and cap.
