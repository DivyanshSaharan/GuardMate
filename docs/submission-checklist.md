# Submission checklist

The [DEV draft](dev-submission.md) follows the official
[submission template](https://dev.to/challenges/hacktoberfest-weekend-2026-10-01).
Required tags: `devchallenge`, `weekendchallenge`, `hf26challenge`.
The published post, not a repository push alone, is the contest entry.

- Verify the video and audio links after the approved repository push. A DEV-native
  video upload is optional; keep the GitHub links as accessible originals.
- Review the first-person story; do not invent friend feedback or a completed delivery.
- Publish the pilot report and its public metrics summary alongside any README/post links.
- Check the public repository links from a signed-out browser after the approved push.
- Review the Tinker comparison: one extra strict planner match, unchanged checked
  success and worse median latency. Category eligibility is the judges' decision.
- Keep the fixed demo heading clearly labelled as presentation; action traces are
  the runtime source of truth. Never use it as fine-tuned inference evidence.
- Keep `.env`, private/runtime audio, databases, private checkpoint paths and weights
  out of Git. The consented demo files under `docs/media/` are intentional public assets.
- Publish on DEV using the required tags and template before **October 5, 2026,
  12:29 PM IST (06:59 UTC)**, per the official challenge page.
- If work continues after that deadline, note post-deadline commits in the README,
  as required by the challenge FAQ. Do not mix later improvements into submission results.

Only Best Use of Tinker is supported by the current partner integration. No Render,
Backboard, ElevenLabs or DigitalOcean usage is claimed. Agent-session sharing is
optional; do not publish credentials or private context in a session export.
